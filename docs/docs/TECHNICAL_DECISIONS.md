## 2. Package & Version Decisions

1. **`@x402/core@2.30.0` & `@x402/hedera@2.30.0`**:
   - Pinned exact versions to ensure protocol wire stability.
   - Used re-exported `@x402/hedera` Hiero SDK primitives (`AccountId`, `Client`, `Hbar`, `PrivateKey`, `TransactionId`, `TransferTransaction`).
   - *Rationale*: Directly importing `@hiero-ledger/sdk` or `@hashgraph/sdk` in sibling dependencies creates dual-install string-brand mismatches where `t.startsWith is not a function` is thrown. Re-exports resolve from a single SDK instance.

2. **`better-sqlite3@11.8.1`**:
   - Zero-configuration, synchronous, file-backed ACID SQLite database.
   - Supports WAL mode (Write-Ahead Logging) and concurrent reads.
   - Pinned prebuilt binaries compatible with Node v22 LTS on Windows 11.

3. **`express@4.21.2`**:
   - HTTP server engine integrating with official `@x402/express` adapter.

4. **`vitest@3.0.5`**:
   - High-performance TypeScript test runner with coverage and mock utilities.

## 3. Network & Currency Decisions

- **Network**: `hedera:testnet`.
- **Mainnet Prevention**: Hard check in `src/config.ts` fails closed immediately if `HEDERA_NETWORK` equals `hedera:mainnet` or contains `mainnet`.
- **Asset**: Native HBAR (`0.0.0`).
- **Precision & Unit Safety**:
  - 1 HBAR = 100,000,000 tinybars.
  - Integer tinybars (`BigInt` / safe integer) are used exclusively for calculation, comparison, and verification.
  - Floating-point representations (`0.1 HBAR`) are only converted using string-based decimal math (`Decimal` / `BigInt`), never raw JavaScript `float` multiplication.

## 4. Facilitator Integration Decisions

- **Hosted Facilitator Discovery**:
  - The service dynamically queries `/supported` on startup.
  - Validates that `kinds` includes `{ x402Version: 2, scheme: "exact", network: "hedera:testnet" }`.
  - Discovers the sponsored `feePayer` account (live: `0.0.9185802`).
  - If the facilitator is unavailable or does not support `hedera:testnet`, the service logs a clear alert and operates in fail-closed mode for protected routes.
- **Fee Sponsoring**:
  - The facilitator sponsors the consensus submission fee using its own fee-payer credentials.
  - The customer's signed transaction specifies the facilitator's fee payer account as the transaction ID payer, while the HBAR transfer debits only the customer's account.

## 5. Pay-to-Unlock Settlement Order Decision

- In accordance with PerPay's post-generation pay-to-unlock architecture:
  1. The AI completion is already generated by Groq and stored in private gateway storage before the customer pays.
  2. The customer requests `GET /api/v1/generations/{generation_id}/result`.
  3. The service checks if the generation is already paid in SQLite:
     - If `CONFIRMED`: releases the stored result immediately (HTTP 200).
     - If unpaid: returns HTTP 402 with `PAYMENT-REQUIRED`.
  4. Customer supplies `PAYMENT-SIGNATURE` header.
  5. The x402 service verifies the transaction structure, submits settlement to the facilitator, and verifies the on-chain consensus record on Hedera Testnet Mirror Node.
  6. **Only after confirmed settlement** is the response payload unbuffered and released to the client.

---

## 6. Service-to-Service Security & Authoritative Boundary

- **FastAPI** is the authoritative source for:
  - User identity, generation status, actual token counts (`prompt_tokens`, `completion_tokens`), and exact invoice tinybar pricing.
- **x402 Service** is the authoritative source for:
  - Payment requirements generation, cryptographic signature validation, facilitator settlement, Hedera transaction verification, and local settlement persistence.
- **Communication Security**:
  - All internal calls (`/internal/v1/*`) require the `X-Internal-Secret` header matching `INTERNAL_SERVICE_SECRET`.
  - Timestamp validation protects against internal webhook replay attacks.
